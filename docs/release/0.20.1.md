# minanode 0.20.1 release notes

0.20.1 adds opt-in uptime reporting with SNARK work, ports OCaml 4.0.4 changes
and fixes SNARK worker and prover failures. It remains a beta release. The
uptime service's operator confirmed that it scored reports from this release's
uptime code. zkApp acceptance remains unqualified.

This release ships the native Linux x86-64 and ARM64 archives. Minaweb and its
downloadable bundle are deferred to the separate
[0.21.0 web-node release](0.21.0.md).

## OCaml 4.0.4 changes

Source comparison found no wire-format, genesis or network-configuration changes
in OCaml 4.0.4. The audited uptime payload, signature-domain and worker sources
are unchanged from 4.0.3. This release ports the following 4.0.4 changes.

- **Protocol-state check.** The node now rebuilds each incoming block's protocol
  state after applying its staged ledger and compares it with the block. A
  mismatch rejects the block as invalid. This is the check upstream
  [MinaProtocol/mina#19901](https://github.com/MinaProtocol/mina/pull/19901)
  added in 4.0.4. The producer and the validator share one state builder. In a
  full staged-ledger replay, 15,897 blocks of the retained replay corpus, seven
  genesis-adjacent devnet blocks and 300 blocks from a captured devnet root
  passed the check. A broader header replay of 41,530 transitions used recorded
  staged-ledger hashes and had no rejections. Devnet block 552017 was not
  checked because its parent is unavailable.
- **Ledger sync.** Ledger sync now clears verified empty subtrees, replaces
  reused subtree contents and indexes, and rejects excess account responses. The
  node no longer broadcasts empty snark-pool messages.
- **GraphQL status queries.** The private GraphQL API adds
  `transactionPoolStatus`, `bootstrapStatus` and `scanState`. The
  `archiveVersionedPrecomputedBlock` mutation returns the upstream error for a
  node without a configured archive. `scanState` reads only the scan tree
  counters, as OCaml does.
- **Archive and fork export.** Archive delivery was checked against fresh 4.0.4
  archive schemas and 4.0.3 schemas upgraded with the 4.0.4 migration. Fork
  export now keeps transaction version 4 for the empty account. Default account
  permissions keep verification-key transaction version 4 across future version
  bumps.
- **References.** OCaml source references were audited against 4.0.4 and
  repinned where the source is unchanged or the change was classified. The
  compiled consensus oracle used in differential tests now builds from 4.0.4.

## SNARK worker and prover fixes

- The worker now proves zkApp account updates whose proofs come from circuits
  with 2^16-row step domains. These jobs panicked the worker on devnet.
  In-circuit division now fails the proof on a zero divisor instead of
  panicking.
- A panic while proving now fails only that job. Previously it left the thread's
  prover state unusable, and every later job on that thread failed until
  restart. This applies to the SNARK worker, the uptime prover and the block
  prover. The block prover thread no longer exits after a panic, which
  previously stopped block production.
- A sweep removed prover panic sites reachable from proof data. A previous proof
  with a step domain over 2^16, or an evaluation of more than one chunk, now
  returns an error. Block proofs are unchanged. The prover test corpus adds
  zkApp jobs that use the xor, rot, foreign-field multiplication and lookup
  gates.
- A new best tip no longer drops stored SNARK work when the pool holds more
  works than the ledger read capacity. The pool reads each prover's account
  once, as OCaml does, and keeps works whose read fails until a later read
  succeeds. A job whose proof is refused stays scheduled, as in OCaml.

## Input validation

Malformed proof data is rejected during verification.

Malformed peer input is rejected at decoding and validation.

Malformed ledger data is rejected with an error, as in OCaml.

## Uptime reporting

Uptime reporting is off by default. Set `--uptime-url` and exactly one of
`--uptime-submitter-key FILE` or `--uptime-submitter-pubkey PUBLICKEY` to enable
it. Set `UPTIME_PRIVKEY_PASS`, even when the password is empty. The key file
must have mode 0600. The public-key option finds a tracked wallet under the
node's `wallets/store` directory. `--snarker-fee` sets the work fee without
starting the general worker. Its default is 0.1 MINA.

The reporter follows OCaml 4.0.4's report format, signature domains and work
selection. It starts at the next slot boundary and then every five slots. That
is 450 seconds with Mesa's 90-second slots. The best-tip report proves a
suitable transaction job before signing. A block without a suitable job is sent
without work. A proving failure skips the report. The next interval cancels an
unfinished attempt. A separate produced-block report carries no work. It retains
the first local completion after its wait begins, even if a fork removes that
block from the best chain. Earlier production events are ignored, as in OCaml.

The reporter skips startup, frontier restore and bootstrap until the node has a
real, non-genesis frontier. It never saves or sends the temporary genesis tip.
Catch-up from an existing frontier still reports, as OCaml does.

`--uptime-dry-run-dir DIR` saves signed request bodies instead of sending them.
A URL and submitter are still required. Dry run still loads circuits and proves
work. `--uptime-send-node-commit-sha` optionally includes the first eight
characters of the build commit. The uptime flags have `MINA_UPTIME_*`
environment aliases.

Nine devnet dry-run reports over eight scheduled intervals passed OCaml's full
blockchain-proof, transaction-proof, SOK and HTTP-signature checks. They covered
five coinbase-only blocks and four payment blocks. No report was sent to an
uptime endpoint. These checks establish local compatibility. They do not
establish service eligibility, registration, credited uptime or service
acceptance.

An optimized devnet circuit-load test measured 549.8 MiB extra resident memory
above a producer for uptime transaction and merge circuits. Loading zkApp
circuits added another 707.4 MiB. The total increment was about 1.23 GiB. These
are process RSS readings after loading, not proving peaks or a hardware sizing
guarantee. Separate proving queues still share CPU and memory with production.

The [uptime operator guide](uptime-reporting.md) includes the local release gate
and the separate owner-approved service-acceptance plan.

### Intended differences from OCaml

Rust keeps the node running when the uptime worker fails. It uses an in-process
worker. OCaml terminates its daemon when the separate worker dies. Rust retries
failed circuit loads on later requests with a backoff capped at 300 seconds.

Rust accepts double-dash long flags and adds environment aliases and disk-only
dry run. It checks key-file mode 0600 but does not require directory mode 0700.
It does not create the wallet directory during lookup. Duplicate public-key
matches are sorted by filename. Its User-Agent identifies mina-rust. Each HTTP
attempt has a 60-second timeout with a 10-second connection timeout. These
operational differences do not change the signed report format.

### zkApp limitation

For the selected terminal zkApp segment, Rust uses the same all-zero SOK digest
as OCaml 4.0.3 and 4.0.4. Both implementations produced a cryptographically
valid proof in the reproduction. OCaml's delegation verifier rejected its
binding to the submitter and fee. zkApp uptime-service acceptance is not
claimed. The local release gate accepts only this exact case as an exception;
every other report must pass full verification.

## Recovery and peer privacy

Ledger faults now trigger resynchronization and report recovery diagnostics.
Invalid genesis inputs return explicit startup errors on native hosts.

Native nodes disable signaling discovery and exchange by default. Operators who
need those channels must opt in with `--webrtc-signaling-relay`. Direct HTTP
signaling still works.

WebRTC service queues now have item and byte bounds, with backpressure for full
send queues and cancellation that releases reservations. Failed channel opens
disconnect and clean up the peer; invalid Identify and Kademlia stream ordering
is rejected. These are service-layer bounds, not a limit on total process
memory.

Native WebRTC transport queues below the service layer are now bounded per
queue, per association and in total. Under aggregate pressure the node drops the
association with the most buffered data. Native HTTP signaling responses are
capped at 512 KiB with a 30-second deadline.

## Transaction pool, producer and consensus

Transaction-pool ledger account reads now run asynchronously with bounded
requests and ordered completion. Failed frontier updates retain their changes
and retry. The producer selects currently available transactions immediately,
without waiting for pending pool reads or reconciliation.

After sleep or catch-up, the VRF evaluator rechecks a delayed delegator table's
epoch, seed, ledger and stake against the current tip and execution time. It
requests fresh data when needed, ignores obsolete replies and includes the
current slot when evaluation can begin there. Remaining-slot statistics now
include the first evaluated slot, correcting the previous one-slot undercount.

Slot classification and production continuation now handle the maximum slot.
Startup in the final epoch no longer overflows computing the next epoch
boundary. The VRF progress cache moves to format version 2 and ignores saved
version-1 progress. A differential harness compares consensus constants, VRF,
epoch data, delegation tables and fork choice with compiled OCaml.

When the clock is in the epoch after the tip's, the producer now evaluates that
epoch at once with the tip's next epoch data, as OCaml 4.0.4 does. Evaluations,
completed epochs and wins are bound to their epoch data. A change of that data
restarts the evaluation and drops wins of the old data. The producer checks the
chosen parent before production. It waits for a complete staking ledger with the
exact hash instead of evaluating an empty table. The VRF cache moves to format
version 3, and results saved in earlier formats are recomputed.

## RPC and GraphQL

The native node retains the RPC additions used by minaweb, including best-chain
headers, block lookup and sync-progress responses. These native APIs are part of
0.20.1; the browser application is released separately.

Account RPC requests before the first best tip now return an empty result and
complete instead of remaining pending. Malformed transaction IDs, hashes and
account keys return errors or empty ledger answers without panicking. GraphQL
query descriptions are corrected, and wide command nonces remain JSON integers
while retaining the existing `Int` schema and input coercion.

GraphQL returns the dummy verification key hash in
`authorizationKind.verificationKeyHash` for signed and unauthorised account
updates, as OCaml does, instead of null.

## Ledger and fork export

`mina ledger export` and `mina fork export` keep token symbols and zkApp URIs
that are not UTF-8 byte for byte, as OCaml writes them. Before, these values
were replaced with U+FFFD, so the export hashed to a different ledger. Ledger
hash, export and fork verification, and `--config` genesis files read OCaml's
raw bytes.

## Upgrade from 0.20.0

1. Stop your node and back up its state, configuration and encrypted keys.
2. Download the archive for your platform. Verify the signed checksum list and
   signed tag with the
   [install guide](https://minanode.org/docs/install/#check).
3. Replace the binary. Check `mina --version` and `mina build-info` against the
   approved 0.20.1 release commit. Keep the previous binary for rollback.
4. Start with the same network and work directory. No state migration is
   prescribed for this patch. A fresh bootstrap remains the fallback if restore
   fails. Back up stopped state before testing a downgrade.
5. Keep uptime disabled unless you intend to configure it. Test disk-only
   reporting first and allow for its extra memory.
6. Review WebRTC signaling configuration. Use `--webrtc-signaling-relay` only
   when you intend to introduce peers through that node. Public minaweb relays
   should retain the restricted defaults.

Docker users should pin `ghcr.io/minanode/mina-rust:0.20.1` after the image is
published. The separate web release does not ship with these native archives.

## Known issues

- Delegation credit has not been confirmed. zkApp uptime-service acceptance
  remains unqualified. Terminal zkApp work has the SOK limitation described
  above.
- Long-run worker memory with zkApp jobs on small machines needs measurement.
- GraphQL `tokenSymbol` and `zkappUri` return U+FFFD for bytes that are not
  UTF-8. Exports and genesis files keep the exact bytes.
