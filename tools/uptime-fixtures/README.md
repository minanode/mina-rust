# OCaml uptime and reporting fixtures

These are **offline test fixtures**, captured from the official OCaml Mina 4.0.2
binary at source commit `84b8d96954b218f372b93f65a071abf528e6bb61`. See the
protocol research for the field definitions, signing rules, backend limitations
and implementation brief.

Every committed private key was freshly generated by OCaml for this experiment.
They are prominently marked `THROWAWAY-TEST-KEY.json`. Never fund or reuse them.
P2P private keys, operator keys and process environments are not fixtures.

## Inventory

- `fixtures/mainnet/`: real uptime request/signature and full version-2 status.
- `fixtures/devnet/`: real uptime request/signature in the testnet domain and
  the default simplified status (seven fields, no version).
- `fixtures/mainnet-retry/`: real uptime request including the optional short
  commit SHA, with receiver responses `503,503,200` per path. Uptime retries
  preserve bytes; subsequent scheduled reports have fresh timestamps.
- `fixtures/node-error-source-derived.json`: **synthetic schema example** from
  `node_error_service.ml:20–39,54–55,117–153`, not an emitted error report.

Each capture directory contains the original HTTP body `uptime-1.json`, its
exact compact signed substring `uptime-data.json`, `node-status-1.json`, the
HTTP records `requests.jsonl`, a private-chain configuration `daemon.json`, the
test signing key and `manifest.json`. The latter records binary hash, source
commit, profile, sizes, data digest, decoded OCaml signature components and
block checksum. The HTTP records preserve headers, base64 body bytes, receiver
timestamps and response status. Raw JSON bodies deliberately retain OCaml
whitespace, field ordering and numeric spelling; do not pretty-print them.

The private chains used `proof.level=none`, 2-second slots, no peers and no
producer. Blocks contain dummy proofs and are **not valid public-chain proof
fixtures**. No `snark_work` is present. No produced-block path, real error,
10,000-byte cutoff or all-eight-attempt exhaustion was executed. The optional
`graphql_control_port` remains absent: its daemon flag is compiled only when ITN
features are enabled, and the installed binary rejects it.

## Checks without an OCaml installation

```sh
python3 tools/uptime-fixtures/check.py
CARGO_BUILD_JOBS=8 CARGO_TARGET_DIR=/tmp/r43e1-signature-target \
  tools/regression/lock.sh build -- \
  cargo run --locked \
  --manifest-path tools/uptime-fixtures/signature-check/Cargo.toml \
  -- tools/uptime-fixtures/fixtures
```

The Python check validates captured bytes, BLAKE2b-256, Base58Check components,
block checksums, Content-Length, fixture shapes, measured retry intervals and a
live loopback recorder round trip. The small standalone Rust executable uses the
repository's pinned `mina-signer` revision to verify **OCaml-generated**
signatures and reproduce them from the generated test keys. It rejects another
network domain, a modified digest and a hex-encoded digest. It is a fixture
checker, not a reporter implementation.

## Generate fresh reference output

From the repository root, with `scripts/ocaml-mina` installed:

```sh
python3 tools/uptime-fixtures/capture_ocaml.py \
  --work /tmp/r43e1-new-mainnet
python3 tools/uptime-fixtures/capture_ocaml.py \
  --work /tmp/r43e1-new-devnet --network devnet --simplified
python3 tools/uptime-fixtures/capture_ocaml.py \
  --work /tmp/r43e1-new-retry --send-commit --statuses 503,503,200
python3 tools/uptime-fixtures/extract_capture.py \
  --capture /tmp/r43e1-new-mainnet --output /tmp/r43e1-new-fixtures
```

Run captures sequentially. The scripts require a **new** private work directory,
create a private TMPDIR, generate their own keys, use a custom private network
ID, seed mode and `--isolate-network true`, bind to loopback, and have no peer
or external-report URL options. They configure only the in-process receiver.
They clear inherited block-producer key settings, never configure a producer,
and terminate their own daemon by PID after success or 90 seconds. Exit 130 is
OCaml's graceful signal shutdown. These private nodes do not join mainnet or
consume public-peer RPC slots. Choose unused slot ports with `--http-port`,
`--p2p-port` and `--receiver-port` if these defaults are occupied. All children
must exit before the next capture.

Fresh capture output varies with generated keys, timestamps and host counters.
Keep the committed output as the deterministic reference for Rust tests.

## Local delivery receiver

```sh
python3 tools/uptime-fixtures/receiver.py \
  --port 3592 --output /tmp/r43e1-delivery.jsonl --statuses 503,503,200
```

It binds only `127.0.0.1`, records any POST path and returns the specified
status sequence independently per path, repeating the last status. It supports
Content-Length and chunked input, records exact body bytes, and never forwards
or registers anything. Stop this foreground process with Ctrl-C. It deliberately
does not validate signatures, registration, block proofs or service eligibility.
